# 中文客户端识别复查（2026-10-26）

本轮由 Tombsong（墓歌）无法识别的反馈触发。汉化维护：Solaris。感谢原作者 [errolgr](https://github.com/errolgr/pd2-trade)，保留 MIT 许可。

## 确认与修复

- 游戏复制出的底材是“精良箭矢 Sharp Arrows”，已有输入别名仅有“精良箭矢”。新增对完整已知英文名称的中英混合识别，并检查已知中文前缀是否与英文身份冲突。
- 同样处理“复生骷髅弓箭手 Raise Skeleton Archer”等技能字段。完整英文名称仍在时，中文前缀乱码不再让已确认的英文身份丢失；不使用模糊匹配修正英文拼写。
- 按本机 ENG、CHI 三份 TBL 的键值增补输入别名，合并保留原有别名。规范底材英文大小写，避免 Winged Helm、Two-Handed Sword 出现假歧义。
- 聚气次数支持 `Charges`、`聚气`、`聚氣`，保留等级、剩余次数和容量。
- 原生剪贴板读取兼容 TBL 的旧式 `0xff c 色号` 标记。只转换这一明确标记，其他无效字节及损坏 JSON 仍拒绝；不猜补引号或数字。
- 排除目录中英文底材名为空的导入记录，并将缺失目录项列入报告。

## 验证方式

`node scripts/audit-game-client-compat.mjs` 可离线重跑客户端输入检查；明细见 [JSON 报告](game-client-audit-20261026.json)。覆盖中文别名、中英混合、括号英文、可逆乱码、英文输入、属性数值与范围、技能筛选、上架输入归一化及触发/聚气格式。

`node scripts/audit-skill-compat.mjs docs/skill-audit-20261026.json` 验证技能选择、官网 URL、查询参数、内部市场参数一致性；结果见 [技能报告](skill-audit-20261026.json)。

另有墓歌完整复制数据回归测试、剪贴板读取优先级测试及原生字节解码测试。覆盖层文件和官网账户登录逻辑未参与本轮修改。

## 明确保留的限制

- “战斗斧”对应 Battle Axe 和 Tabar；“重击／重擊”存在两个技能。无足够上下文时保持不可确定，不强行猜选。
- 装备死亡施法（197）和地图怪物死亡施法（453）共用文字模板。无编号时不据文字发明精确筛选；明确的装备属性编号仍可识别。
- 目录中 t99、t55、t54 没有英文底材名，列为未覆盖，未把空字符串作为合法底材。
- 已经丢失的引号、字节或缺少身份的纯中文乱码无法可靠还原。原生读取优先取游戏写入的原始数据，但本轮没有逐件游戏内实测全部物品，也没有用用户账号批量进行官网交易。
- 自动化检查通过表示报告范围内的数据与参数一致，不等于所有汉化补丁、过滤器和未来客户端版本均已实测。
