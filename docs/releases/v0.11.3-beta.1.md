# 0.11.3-beta.1 上架兼容实验版

本地实验版本，基于 0.11.2。尚未发布到 GitHub Release 或正式自动更新通道。

特别感谢原作者 **[errolgr](https://github.com/errolgr)** 与 **[errolgr/pd2-trade](https://github.com/errolgr/pd2-trade)** 的所有贡献者。汉化与兼容维护：Solaris；沿用 MIT 开源许可。

## 简短更新

- 对可逆的 UTF-8 → Latin-1 / Windows-1252 乱码先恢复中文，再按客户端别名转换为英文底材、固定物品名及技能身份。
- 在每次官网仓库匹配前规范化，包括旧版本保存的排队记录。未知或不可恢复的底材明确报错，避免静默进入“等待服务器同步”。
- 排队每 15 秒请求最新仓库，绕过旧候选缓存；同轮并行检查合并仓库请求。
- 排队出现多个候选时保留记录并显示选择界面，由用户决定；原先排除的物品 hash 继续排除。
- 显示检查失败、登录失效与底材识别错误；把倒计时改为“自动等待期限”，避免误认为官网必须等待 15 分钟。

编码修复只处理游戏复制输入。价格、备注不参与翻译；上架依然提交官网返回的原始物品数据和 hash，不用翻译后的复制数据重建官网物品。没有修改窗口覆盖层、官网登录协议或自动更新设置。

## 本地验证范围

- 装备输入、市场接口、真实仓库匹配、缓存、历史队列和排队界面专项检查通过，覆盖用户提供的盗墓者乱码底材。
- 英文、正常中文和该乱码输入均匹配到同一模拟官网仓库对象；只提交被选中的官网 hash、属性与孔数。
- 技能、查价链接、剪贴板与上架入口回归检查通过；全技能静态参数审计 7,283 项通过。
- 真实应用 TypeScript 类型检查通过。

这些检查使用本地测试数据，没有使用用户账号调用实际交易上架接口；不等于已在游戏或真实官网账号中通过。

## 游戏内测试

1. 完全退出旧版程序，再安装本实验版，在设置中核对版本为 **0.11.3-beta.1**、游戏账号、天梯与普通／专家分区。
2. 先查看现有排队记录。旧队列仍会按原来的上架意图继续处理；不需要继续上架的记录请先取消。
3. 使用之前已在官网共享仓库可见的“盗墓者”，鼠标指向装备后按 **Ctrl + L**（自定义快捷键以设置为准）。查看能否直接找到官网物品。
4. 比对孔数及词缀，输入价格或备注后上架；到官网核对实际物品、备注与价格。若出现多个候选，手动选择正确物品。
5. 分别用英文客户端与汉化客户端复制装备，验证查价和上架。带职业技能、触发技能与聚气技能的装备也应复测。
6. 若仍等待，记录排队中的具体提示；如果提示“已排除入队时的候选”，取消该队列后重新复制并选择目标。

无法还原的数据（例如字节已丢失为问号、替换字符或 JSON 引号已损坏）不会被猜测重建。请保留原始复制文本和报错截图，供下一轮定位。
