# 中文版自动更新

感谢 [errolgr](https://github.com/errolgr/pd2-trade) 开源原作。此更新通道由 Solaris 维护，独立于英文版。

## 用户使用

手动安装一次 0.11.2 后，自动检查默认开启。软件启动约 5 秒后和运行期间每隔 30 分钟检查一次；发现新版显示中文提示，点击“下载并安装”才下载、验证签名、安装并重启。关闭提示后，可在“设置 → 更新”中手动检查和安装。

首次从早期中文版迁移时启用检查；之后用户主动关闭的偏好会保存。更新不读取 PD2 登录凭据，也不修改游戏文件。更新时查价器会关闭并重启，请先完成当前交易操作。检查失败不影响使用，下一轮重试；下载、签名或安装失败不主动重启。

旧版本未启用更新插件，需要手动安装一次引导版本。收到更新提示需要能访问 GitHub；这不是即时消息推送服务，软件未运行或网络不可用时不会即时收到提示。

## 发布新版本

1. 在 `main` 上修改源码，更新五处版本：`package.json`、`package-lock.json`（含根包）、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 中的应用版本。
2. 在 `src/assets/changeLog.ts` 添加简短中文记录，创建 `docs/releases/vX.Y.Z.md`，保留原作者致谢。
3. 运行类型检查、更新专项检查与 `node scripts/verify-updater.mjs config`，提交并推送源码。
4. 创建并推送对应的 `vX.Y.Z` 标签。GitHub Actions 的 `Build and publish signed Chinese update` 自动安装依赖、构建 Windows x64 包、签名、上传草稿并验证远端附件，最后发布正式版及 `latest.json`。
5. 确认工作流成功，并核对安装后的“设置 → 更新”。不要移动已发布标签或替换正式版附件；修复请递增版本。

也可在 Actions 中手动运行同一工作流。已发布版本只验证已有资产，保持原附件不变。草稿中若有同名但内容不同的资产会停止发布，需要维护者检查并清理该未发布草稿后重试。

流水线只在版本标签或手动触发时运行。普通提交不会向用户发布更新。每次发布构建后仍应在真实游戏环境验证主要功能。

## 更新通道与签名

- 更新源：`https://github.com/SolairsVIP/pd2-trader-chinese/releases/latest/download/latest.json`。
- Windows 目标：`windows-x86_64`，NSIS 安装包及 `.sig` 签名。
- 应用身份：`com.pd2-trader.chinese`。公钥 ID：`C4778CD189119CE3`。
- 更新签名私钥和密码分别存放在仓库 Actions Secrets：`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。
- 私钥备份位于维护者电脑仓库外的 `Z:\PD2 Trader\update-signing-private`；加密密码的 DPAPI 备份绑定创建它的 Windows 用户环境。应另行将私钥和密码安全备份到维护者自己的离线密码管理器。
- 私钥、密码及访问令牌不得提交、打印或放进 Release。公开公钥可以随源码发布。丢失私钥会导致已安装客户端拒绝新密钥签名的更新，不能随意重新生成替换。

本地构建时，通过环境变量提供签名私钥和密码，运行 `npm run tauri -- build --bundles nsis -- --locked`。可先运行 `node scripts/publish-update.mjs --prepare-only` 生成经验证的发布附件；实际发布需在环境中提供有仓库写权限的 `GITHUB_TOKEN`，再运行 `node scripts/publish-update.mjs`。脚本会核对标签提交和签名，先发布草稿，验证从 GitHub 下载的附件后才转为正式版。

公开发布后可执行 `node scripts/verify-updater.mjs live --expect-version X.Y.Z`，匿名下载真实安装包并验证签名。签名机制依据 [Tauri 官方更新文档](https://v2.tauri.app/plugin/updater/)。
