# 腐化区提示

**腐化区提示原作者：Blyat。** 感谢提供原始工具、中文区域数据和说明。

集成测试版本：0.11.7-beta.2。此功能不属于已经发布的 0.11.6。

## 使用

- 默认开启，只在游戏处于激活状态时显示；提示卡默认吸附在当前屏幕工作区顶部中央，默认宽度 720 像素，高度约 56 像素；长中英文自动换行并适配高度。
- 默认细横条显示当前区域中文名、对应英文名、加大加粗的幕数和倒计时；中文居中放大，英文完整显示，大号倒计时清晰醒目，悬停可看下一轮与完整名称。点击箭头或双击横条展开／收起未来四轮，展开列表同样显示中英地名。
- 拖动标题栏改变位置，靠近顶部（24 像素内）松开恢复顶部吸附；标题栏的恢复按钮也可恢复居中。
- 在“设置 → 腐化区提示”调整宽度（480–960 像素）、颜色和展开状态。小屏幕会自动缩小。
- 默认跟随软件主题；可选择暗金、浅色配色，或自行调整背景、文字和强调色。
- 选择角色主要伤害类型（闪电／冰冷／火焰／毒素／物理／魔法），保存选择后显示当前和未来四轮的免疫参考；横条左侧点击轮换，展开或设置中可直接选择。默认“不提示”，不会猜测角色流派。
- 刷图用语统一为：无免疫“爽刷”、少量免疫“可刷”、大量免疫“勿刷”。现有参考表只记录免疫有无；数量未核实时仍显示“存在免疫”，不凭空划分少量或大量。缺失区域明确显示“资料待核对”，展开显示理由。
- 免疫提示位于横条右侧、倒计时左边；未来四轮的免疫提示也靠右显示。倒计时数字为 30 像素，时间框至少 110 像素宽。展开区底部只保留“腐化区提示原作者：Blyat”，资料来源及限制保留在设置和文档中。
- 点击关闭隐藏提示，可在设置或右下角“更多 → 腐化区提示”恢复。
- 不使用独立置顶原生窗口，不改变既有覆盖层、焦点和点击穿透算法；只注册实际提示卡大小的面板。切出游戏隐藏，不遮挡其他程序。

这是**建房时间表预报**，不会读取当前房间或服务器状态。已有房间可能保留建房时区域，请以游戏公告为准。系统时间不准确或服务器改变算法时，预报可能不符。无需登录或联网，不读取游戏进程，不修改客户端文件。

## 数据和算法来源

用户提供目录 `111` 中的 `PD2腐化区域.exe`、`zones.json`、`使用说明.md` 和 `地图名称核对.md`。区域数据包含 37 组、118 个地图引用，保留原始英文名称和客户端中文译名。

- 程序 SHA-256：`53376ff4d028066a816a58e7ae89c5f81a57fc371a57300d5ae7374d59dc8e74`
- 数据 SHA-256：`c0ab674dc1f632c7c246b1c666accaefa869bbcc3a0f62fcaa87049718c997e1`

仅静态解析托管程序元数据与 IL，未运行用户提供的 EXE。`ZoneAt` 为 MethodDef 第 4 行，RVA 8396；`NowMs` 读取 UTC Unix 毫秒，静态纪元是 1970-01-01 UTC。移植公式为：

```csharp
static int ZoneAt(long ms) {
    long slot = ms / 900000 * 900000;
    long seed = slot / 900000 + slot / 86400000;
    return (int)(((seed * 214013 + 2531011) / 65536) % 32768 % 37);
}
```

整数计算不截断到 32 位。JavaScript 移植使用 BigInt，按 UTC 15 分钟边界更新，界面使用本地时区。原工具说明引用 [HiimPD2 区域时间表](https://hiimpd2.com/cz)；本项目没有复制该网站的区域评分，也不运行或下载第三方脚本。

## 验证范围

### 免疫参考来源及限制

六类免疫有无参考 [Hiim PD2 作者公开的 cz-data.js](https://github.com/Maaaaaarrk/Hiim-PD2-Resources/blob/main/cz-data.js) 中 `zoneImmunities`，2026-10-26 经公开 GitHub 源码页只读核对。这里只记录 37 组区域是否出现某类免疫的事实，不复制脚本、不执行远程代码、不复用区域评分或抗性数值。`immunities.json` 区域编号逐一对应 Blyat 区域英文名称，测试检查所有编号及六类枚举。

这是社区参考资料，未独立从当前服务器怪物表验证；公开仓库与网站也可能不同步。没有按子地图或怪物分布的数据，因此不声称“全区免疫”或计算免疫密度，不承诺完整覆盖当前赛季。未计破免、双修、佣兵及精英词缀，也没有实现 Infinity 破免阈值判断。实际适合与否仍需游戏实测；发现差异应修订资料而非改轮换算法。无已知数据时不会给出适合建议。
