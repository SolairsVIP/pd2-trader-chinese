通过范围：

- 用户盗墓者样本的混合 Windows-1252/C1 乱码底材还原；英文、正常中文、乱码均进入实际仓库匹配器并得到同一个模拟官网物品。
- 正常英文 JSON 原样保留；正常中文、弯引号和重音字符不盲目重编码；仅接受可逆、合法且恢复出汉字的 UTF-8 数据。
- 不猜测已丢失字节、损坏引号或未知底材；明确显示识别错误。
- 历史队列的匹配也经过规范化；请求最新仓库时绕过五分钟缓存；并行仓库读取合并，失败后可以重新读取。
- 原来排除的 hash 继续排除；多个新候选不自动上架，保留队列并让用户选择。
- 模拟上架 POST 使用官网原始对象、hash、属性和孔数；不改动官网对象，不把游戏输入重建成官网物品。
- 仓库请求仍在进行时取消排队，返回结果不会再上架；瞬时请求失败显示错误且下轮可恢复。
- 技能解析、官网查价链接、剪贴板读取、上架入口回归检查通过。

## 实测边界

没有证据证明用户之前的那次队列内部一定保存了乱码；本次修复的是已复现的编码兼容缺陷和缓存等待路径。账号、分区、登录、官网同步以及初始候选被用户排除等原因仍可能造成排队，需按界面具体提示判断。

未改动 Rust 覆盖层、窗口焦点、官网登录授权流程、自动更新提示与用户点击安装逻辑。安装包没有在本机覆盖安装，也没有做游戏内或跨版本真实安装测试。

游戏内步骤见 [实验说明](releases/v0.11.3-beta.1.md)。本实验版保持源码与 MIT 许可可获取，并继续在 README 醒目感谢原作者 errolgr。
